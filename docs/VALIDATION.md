# 隔离环境验证结果

日期：2026-10-01。所有数据库、Redis 和应用实例均为临时隔离实例，没有部署到业务环境，没有操作实际业务数据库。

## 环境

Windows 本机、Java 21.0.10、Maven 3.9.15、Node.js 24.18.0、MySQL 8.4.9；Redis 7.4.11 运行于本机 WSL Ubuntu。应用、主库、Redis 均在本机，小规模测试数据，结果不代表真实部署容量。Prometheus promtool 3.15.0。

## 自动化检查

后端执行以下命令（连接参数指向隔离库）：

```sh
mvn -B -f '脚手架后端接口/itmk-base-parent/pom.xml' verify \
  -Dauth.redis.port=16389 \
  '-Dauth.mysql.url=jdbc:mysql://127.0.0.1:13389/jsj_reliability_tests?serverTimezone=UTC'
```

**54 项通过，0 失败、0 错误、0 跳过**，其中 20 项真实 MySQL 测试；真实 Redis 测试覆盖刷新轮换与重放。测试仅在库名为 `jsj_reliability_tests` 时启用，不能指向业务库。

MySQL 用例包括：Flyway V1–V5 校验和重复启动；旧库明确 baseline 后保留既有菜单；脏数据迁移失败且不删数据；唯一约束、外键、执行计划；权限修改提交后旧 Redis 缓存仍存在但后续请求被拒绝；缓存读写故障回源；主库故障不能使用旧缓存授权；事务回滚同步回滚权限版本；密码重置、禁用、删除、旧版本会话和持久化退出撤销；审计接收/变更/完成三种故障及事务回滚；五分钟审计超时的时区一致性；空库管理员初始化及 BCrypt。

前端：19 项认证/路由测试通过，TypeScript 检查及生产构建通过。npm audit 检查结果为 0 已知漏洞。仍有超过 500 kB 的构建体积警告，未把这项检查作为实际首屏性能证明。

Flyway Maven 插件对同一库成功执行 `flyway:validate`，识别 SQL 迁移及 Java V3，共 5 个版本。Promtool 配置检查和告警规则测试通过，共 10 条规则。Node 运维脚本语法检查通过。

## 实际 HTTP 压测

通过正常密码/验证码登录取得临时 JWT，三个实际 API 轮询：用户信息、菜单列表、用户分页。测试装置只在隔离 Redis 中准备验证码；产品登录逻辑未增加绕过。每个响应同时校验 HTTP 与业务 code，包含真实鉴权、数据库版本检查和持久化请求审计。

| 场景 | 运行时长 | 请求数 | 吞吐量 | p50 | p95 | p99 | 错误 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 10 并发，无思考时间 | 30.021 秒 | 11,531 | 384.10 req/s | 24.79 ms | 35.05 ms | 46.24 ms | 0 |
| 30 并发，无思考时间 | 30.025 秒 | 26,584 | 885.40 req/s | 32.87 ms | 49.72 ms | 64.67 ms | 0 |

两轮通过 p95 < 500 ms、错误率 ≤ 1% 的测试预算。这是本机短时封闭模型结果，没有证明峰值到达率、长时间稳定性、大数据量、真实网络、故障切换或写入接口容量。不能据此承诺生产吞吐量。正式容量验收应使用预发布环境和真实数据规模。

CI runtime 脚本另经本机 5 秒检查通过：readiness、独立指标端口、真实登录、认证压测与超级管理员审计查询。管理端口指标请求返回 200，业务端口未认证指标请求返回 401；HTTP 延迟直方图、连接池指标和审计待完成指标均存在。没有配置或发送真实外部告警通知。
