# 安全、可靠性与性能改进

审查日期：2026-10-01。范围为本仓库的管理后台和 API 源码；没有部署或修改业务数据库。

## 已处理的问题

| 原有问题 | 改进 |
| --- | --- |
| 角色授权接口缺少操作权限检查，普通管理员可以分配超出自身范围的角色或菜单 | 操作权限与数据库中的当前管理范围双重检查；管理员账户和高权限账户受保护；菜单定义修改仅限超级管理员 |
| 用户实体直接绑定请求，可能改写管理员标记、账户状态和密码；列表返回密码散列 | 使用白名单请求 DTO，拒绝额外字段；编辑显式更新允许的字段；密码仅可写入，列表 SQL 不读取密码 |
| 重置密码统一为固定弱密码 | 管理员明确输入新密码；新增、重置和修改密码要求 12–64 字符且 UTF-8 不超过 72 字节；已有短密码仍可登录 |
| 角色权限清空导致空批量 SQL，删除关联数据缺少事务保障 | 空列表允许清空；保存和删除在事务内完成；先删关联表再删主体；锁定角色/用户避免部分并发写入问题 |
| 缓存删除与回源并发时旧权限可能写回；事务回滚仍失效缓存 | 数据库版本与业务修改在同一事务提交；Redis 键包含当前版本，旧缓存即使仍存在也不可达；读权限前后校验版本 |
| 菜单树反复遍历、循环或极深层级导致异常 | O(n) 索引构建和迭代遍历；新增/修改检查循环、父节点类型、孤儿节点与最大深度 32 |
| 分页参数没有上限；异常可能暴露内部信息或被误认成登录失效 | 每页最多 100 条、页码最多 100 万；统一参数、权限、冲突和基础设施故障响应；Redis 故障返回 503 并保留客户端会话 |
| Cookie 认证写接口缺少浏览器跨站请求防护，关闭了 frame protection | 所有 `/api` 写请求必须带 `X-Requested-With: XMLHttpRequest`；拒绝 `Sec-Fetch-Site: cross-site/same-site`；保持 CORS 默认禁止，恢复 frame deny |
| 数据库及 JWT 密钥写在配置中，SQL 输出可能泄露信息 | 改为环境变量；JWT 密钥至少 32 字节；关闭 SQL 打印；日志滚动并带请求 ID，持久化请求/变更审计，详情仅保存白名单权限字段，不记录凭据 |
| 老旧或闲置依赖、开发工具进入生产包、图表全量打包 | Spring Boot 3.5.16、MyBatis-Plus 3.5.17、Java 21；移除闲置高风险依赖；升级 npm 锁文件；图表仅加载使用的组件并延迟到仪表盘 |
| 空权限账户跳转循环，多级动态路由注册错误，浏览器控制台输出业务对象 | 单独记录初始化状态；子路由保持父子关系，只注册顶层路由；清理调试日志 |

登录策略保持不变：访问令牌 15 分钟，用户真实操作续期，空闲 30 分钟退出；轮换刷新令牌存放 HttpOnly Cookie。后台轮询不能延长空闲时间，不新增连续登录时长上限。

## 启动与兼容性

必须配置 `DB_USERNAME`、`DB_PASSWORD`、`JWT_SECRET`；应用不会回退到原来硬编码的凭据。`DB_URL` 默认连接本机的 `itmk`，实际库名不同须显式指定。Redis 使用 `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`，默认本机 6379；`REDIS_DATABASE` 默认 0。数据库初始化及已有库升级见 `RELIABILITY.md`。

开发 HTTP 使用默认 `test` profile。将来正式上线必须设置 `SPRING_PROFILES_ACTIVE=prod` 并使用 HTTPS；该 profile 强制 Secure 刷新 Cookie。反向代理应让前端和 API 同源。本次没有上线。

原来提交过的数据库口令和 JWT 密钥应在实际环境更换，旧 Git 历史仍含原值；不要重新使用这些值。切换 JWT 密钥会使旧访问令牌失效。仓库忽略环境文件和日志。

外部 API 客户端也必须发送上述自定义请求头。重置密码接口现在要求 `{ "userId": 123, "password": "明确设置的新密码" }`；普通编辑接口不再接收管理员标记、状态字段或密码。升级后需要确认超级管理员具有现有菜单操作权限，普通管理员按权限范围分配角色。

## 验证

后端 Java 21 下执行 `mvn -f 脚手架后端接口/itmk-base-parent/pom.xml verify -Dauth.redis.port=16389`。隔离 Redis 中运行会话、轮换与重放测试；H2 的 MySQL 模式运行基础安全回归；追加 MySQL 8.4 集成测试，验证真实迁移、唯一约束/外键、事务回滚和故障注入。包含真实 MySQL 的执行命令和结果见 `VALIDATION.md`。

前端执行 `npm ci`、`npm run test:auth`、`npm run build`、`npm audit --audit-level=high`；认证与路由测试共 19 项。类型检查与生产构建通过。审查时 npm audit 为 0 已知漏洞；这不代表所有代码均不存在安全问题。

同一升级后依赖集对比：首屏主 JS 从约 2348 kB 降到 1205 kB，减少约 49%；gzip 从约 775 kB 降到 391 kB。仪表盘图表单独约 531 kB，进入该页面仍需下载。仍有超过 500 kB 的构建警告，尚需按实际使用场景优化 UI 组件加载。这是产物体积比较，未测量真实网络下的首屏耗时。

`.github/workflows/ci.yml` 在提交和 PR 上运行后端、真实 MySQL/Redis、运行实例压测、备份恢复、监控规则与前端检查，不含部署步骤；Dependabot 每周检查依赖更新。
